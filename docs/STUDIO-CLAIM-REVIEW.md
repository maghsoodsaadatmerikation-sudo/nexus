# NEXUS Studio — local claim-review foundation (23 November 2026)

## Purpose
AI answers can contain plausible but unsupported factual claims. This module prepares an **unverified reading checklist** for the human reviewer. It does not make judgments, score truth, call a model, search the web, or assign authority. It follows the NEXUS separation between machine assistance and human judgment.

## Implementation

`web/studio-claim-review.js` exposes `globalThis.NexusClaimReview.review(text)` and `checklist(text, language)`. Both run locally with no network, storage, model, or dependency. The input limit is 24,000 UTF-16 code units. The module considers at most the first 12 distinct prose candidates (numbers/dates, causal/associational language, comparisons, or general declarative statements). It excludes Markdown fenced code, simple headings, table rows, questions, and certain instructions. Every returned candidate is **not-checked**, and the report explicitly sets `verified:false`. The checklist supports English (`en`) and Persian (`fa`), and is plain Markdown that the operator can inspect before manually saving or sharing.

A small pattern-based credential preflight stops extraction and Markdown checklist export when recognizable GitHub, API, AWS, Bearer or private-key shapes appear. Only fixed category names are returned on block. This detector is **not comprehensive DLP**, so it can miss personal data, unknown or encoded secrets, and may flag harmless test strings.

## Increment: transient human evidence notebook (23 November 2026)

Each extracted model-answer claim has an expandable **Add human source note** editor. A user may enter one HTTPS source address (maximum 1,000 characters), an exact ISO publication date, a short manual note (maximum 500 characters), and their own assessment: *not assessed*, *appears to support*, *appears to contradict*, or *inconclusive*. A support/contradiction assessment is rejected unless an HTTPS URL **and** syntactically valid publication date are entered. Only user-entered inputs are recorded; NEXUS never opens the URL, reads the article, checks author/date accuracy, scores confidence, or decides truth.

The engine re-derives the exact claim from the original model answer and rejects unknown IDs, forged fields, malformed dates/URLs, overlong text, known credential patterns, or a review blocked for credentials. Its receipt has fixed \`verification=not-independently-verified\`, \`source_retrieved=false\`, and \`authority=none\`. The report generator revalidates the annotations, refuses duplicates, and never invents a source. A human may explicitly copy a plain-text Markdown review report after a separate unencrypted clipboard confirmation.

All notes are held **only in memory inside the open per-answer panel**. Closing the panel, re-rendering, switching chats/language, or locking discards them; they are not added to encrypted project archives and are never sent to providers. No automatic saving, exporting, analytics telemetry, or background source lookup occurs. The clipboard becomes an external plaintext copy only after affirmative consent; the user must separately manage that copy. URL validation and pattern scanning do not imply comprehensive privacy protection or source trustworthiness. UI uses inert DOM text, not HTML for statements or notes.

Synthetic Node tests and actual Chromium narrow/wide acceptance cover invalid source schemes, wrong dates, forbidden assumptions, confirmation/clipboard boundaries, isolation from chat archives, and zero additional network calls. Generated HTML and static offline cache digests must be checked at the exact PR head before merge. The feature is **not deployed** merely because the source and built files exist.

## Increment: source text / quotation presence check (23 November 2026)

The user may manually paste an excerpt of the independently obtained source (30–12,000 UTF-16 units) and an exact 30–400-character quotation, in addition to the source HTTPS URL and publication date. NEXUS runs a deterministic, local, case-sensitive string-presence test after NFKC and whitespace normalization. Results are only **present-in-user-paste** or **not-found-in-user-paste**, and disclose the matching count (capped at 99). The user may paste a forged document or excerpt; this feature does **not** authenticate it, validate the web page, assess the quote's relevance, resolve contradiction, or determine truth.

Source text and quotations are pattern-scanned for recognizable credentials (a limited heuristic) and never sent to a model, external website, or search endpoint. They stay in the open panel as unsaved transient state. The explicitly copied report may include the selected quotation and string-presence result, **but not the pasted source document**. The report generator re-runs the same check on its transient inputs and refuses unknown fields or fabricated "verified" flags. Closing the panel or changing the conversation/language clears these inputs.

The isolated Chromium test now exercises present/missing quotations, secret-shaped inputs, no network, explicit clipboard confirmation, omitted document text and ephemeral state; the Node test verifies malformed provenance, length limits, local matching, missing quotes and misleading claim-verification flags.

A regression in the prior plain-Markdown escaping helper was also corrected. The helper now escapes each character via a callback, so punctuation cannot accidentally interpolate an unrelated program source fragment into copied review notes.

These are checks of **user-pasted text**, not real web evidence. Future opt-in source retrieval would need a separate, security-reviewed proxy and clear user consent, SSRF/redirect controls, domain trust policy, caching/privacy review and real-source attribution. It is not part of this draft.

## Increment: explicitly reviewed browser source opening (23 November 2026)

A reviewer can select **Open source website / بازکردن وب‌سایت منبع** beside an entered HTTPS source URL. This is the first intentional navigation step toward an external source, **not a model/tool retrieval operation**. The URL and hostname are validated synchronously with the original answer and claim ID. Unsupported schemes, userinfo, local hostnames, single-label names, reserved/private-network suffixes, numeric IPs, IPv6 literals and nonstandard ports are rejected. Ordinary public-looking DNS names are syntactic candidates only, not trusted publishers.

A browser-native consent dialog shows the exact parsed hostname and warns that opening the **full URL** contacts a third-party site, which may track the visit or redirect. Only a separate affirmative click triggers \`window.open(fullURL, '_blank', 'noopener,noreferrer')\`. Neither opening the link nor declining consent changes the claim assessment, opens a source automatically, stores a URL in the project, or initiates a \`fetch\` from NEXUS. Browsers may block a popup; UI reports the action as **requested**, never as confirmed completed. A destination may redirect or be malicious after opening, and the lack of a referrer header does not guarantee anonymous browsing.

The pure \`planSourceOpen\` helper has fixed \`source_retrieved=false\`, \`source_verified=false\`, \`claim_verified=false\` and \`authority=none\`. Synthetic Node tests reject localhost, IP literals, internal hostnames, non-HTTPS and userinfo. Narrow/wide Chromium acceptance stubs \`window.open\` and confirms no navigation on decline, exact URL only on approval, requested \`noopener,noreferrer\` and no additional background network fetch.

No web scraping, remote source parsing, independent citation retrieval, claims scoring, billing, token transmission, or public deployment is represented by this feature. Any future proxy-backed web research needs a separate reviewed consent, server-side SSRF and redirect protection, provider/source provenance, anti-injection boundaries and network/privacy tests.

## Increment: user-consented Crossref DOI metadata lookup (23 November 2026)

NEXUS adds a separate DOI input under a selected claim, for **Crossref-deposited bibliographic metadata only** (title, publisher, type and optional deposited publication date). The API is Crossref's documented public REST endpoint \`GET https://api.crossref.org/works/{encoded DOI}\`. It is not an article full-text fetch, a general search engine, a publisher-authenticity check, or a factual verdict. This feature is limited to browser CORS; request failure or a publisher without Crossref metadata must be explained rather than bypassed through arbitrary hosts or a permissive proxy.

Before **any request**, the input must match a bounded DOI syntax, the original claim is revalidated, and the user must explicitly confirm disclosure of **only the DOI** (along with their ordinary network IP address) to Crossref. NEXUS does not transmit the claim, chat thread, project notes, manual source text, model tokens or gateway credentials. The request fixes \`credentials:'omit'\`, \`redirect:'error'\`, \`mode:'cors'\`, \`referrerPolicy:'no-referrer'\`, \`cache:'no-store'\`, method GET, an expected JSON \`Accept\` and a ten-second timeout. A separate AbortController cancels an in-flight lookup when the panel closes or Studio re-renders/locks.

The reader verifies success status, exact response URL, JSON media type and a **64 KiB streaming response limit**, rather than calling an unbounded \`response.text()\`. It also rejects a returned DOI that does not equal the requested canonical DOI. The metadata fields are bounded and rendered as inert text; the entire JSON response is not exposed in the chat or retained. A local SHA-256 digest of the **exact JSON response bytes**, response size, DOI, retrieved title/publisher, metadata scope and a *client-clock* timestamp form a temporary receipt. The hash is a local reproducibility fingerprint, not an independent Crossref signature, evidence of document integrity on the publisher's site, or proof of publication date. The server's Crossref-deposited fields may be inaccurate or outdated. The receipt explicitly marks \`source_retrieved=true\` (only API metadata), \`publisher_verified=false\`, \`claim_verified=false\`, \`authority=none\`.

Synthetic Node tests cover no request before consent; DOI validation; exact HTTPS host/path; privacy request options; response-origin checks; JSON content type; response size; returned-DOI mismatch; cancellation; and misleading truth claims. Browser tests use a **mock Crossref response, not a real provider call**, to verify the actual chat UI on narrow and wide Chromium, including consent denial, safe rendering, cancellation, no archive persistence and no request before user approval. They do not prove live CORS availability, factual accuracy, API uptime, or a physical phone/device.

**Deploy boundary:** Stacked draft feature only; no merge or public release. Future web-source retrieval must be a separate consent and server-side reviewed security project (network address resolution, redirect and rebinding control, host allowlists, content sandboxing and provenance). Crossref metadata is not independent scientific fact-checking.

## Increment: explicit Europe PMC full-text XML and literal quotation matching (23 November 2026)

NEXUS now offers a separate PMCID entry and a button to compare a **user-selected exact quotation** (30–400 UTF-16 units) against a fetched Europe PMC **article body**, for full-text XML available through its fixed public REST endpoint \`https://www.ebi.ac.uk/europepmc/webservices/rest/PMC{id}/fullTextXML\`. The user must supply a syntactically valid PMCID, and must independently approve transmission of that PMCID and the ordinary connecting IP to the Europe PMC service. **No claim text, quotation, user notes, project history, or model credentials** are transmitted in the request. DOI lookup and user-entered source note functions remain separate.

The browser CORS GET has **one fixed hostname**, \`redirect:'error'\`, \`credentials:'omit'\`, \`referrerPolicy:'no-referrer'\`, \`cache:'no-store'\`, explicit XML Accept, 12-second timeout, and abort on closing/refreshing/locking the review panel. Responses must be HTTP 200 with exactly the planned URL, an allowed XML content type, and at most **1 MiB** including actual streamed bytes. Invalid UTF-8, XML entity declarations, internal-subset or ambiguous DTDs, XML parser errors, missing article body, missing/wrong PMCID and bodies above **240,000 UTF-16 units** are rejected. A simple external **JATS article DOCTYPE** may be accepted *only by stripping the declaration before DOMParser*, never resolving, loading or contacting the external DTD. No unsafe parser fallback, alternate mirror, proxy or redirect is attempted.

The Europe PMC quotation input is **separate** from the previous human-pasted-source quotation editor; a remote text lookup therefore cannot leave behind a partial human note that blocks manual evidence saving. This was exercised by an integrated browser regression test.

The downloaded article XML stays in temporary JavaScript memory. Parsing uses the browser's *inert* \`DOMParser('application/xml')\`; only the XML article ID, article title and normalized text of the body are inspected. Full XML and extracted article body are **never** rendered as HTML, sent to a model, added to the encrypted chat archive, copied to the clipboard or put in an evidence report. The receipt shows only article title, response byte count and SHA-256 fingerprint, browser-clock time, PMCID, normalized body length, and whether the exact selected quotation appears (case-sensitive after NFKC + whitespace normalization); match count is capped. The quote need not correspond to the particular claim, and a text match **does not prove scientific accuracy, publisher authenticity, source licensing, or that the claim is supported**. A mismatch likewise is not evidence that the claim is false. It does not automatically change the human review assessment.

This is scoped to Europe PMC full-text XML available through the endpoint; coverage is not all publications and is not certified as open-license redistribution. A CORS failure or a size/DTD rejection is expected to fail explicitly. Synthetic Node tests cover invalid PMCID and quote, no network before consent, blocked redirects, content type, size caps, matching and mismatching XML IDs, disallowed DTD/entity declarations, cancellation, and truthful receipt fields. Chromium wide/narrow tests simulate the API with fixtures, assert consent-before-fetch, no credential/referrer transmission, inert markup, absence of full article body from the UI and archive, and cancellation on close. **No real Europe PMC call or physical device test was conducted by these synthetic fixtures**, and CI PASS does not demonstrate live API availability.

This feature remains in a stacked draft PR only. Static HTML, offline asset bytes, cryptographic package integrity and all CI tests must pass at the exact head before any consideration of merging. Publication and broad web scraping remain out of scope.

## Increment: safe JATS DOCTYPE normalization and source-section context (23 November 2026)

Some legitimate Europe PMC/JATS article XML files have a *simple* external \`<!DOCTYPE article PUBLIC ...>\` or \`<!DOCTYPE article SYSTEM ...>\` declaration. The earlier reader rejected all DOCTYPEs, so it could needlessly fail on an otherwise readable article. The normalized parser now accepts **only a single, short, simple, external article declaration** near the beginning of the document; the declaration is removed from the XML string before the browser's inert DOMParser sees it. **No external DTD is ever fetched or resolved by NEXUS**. Any \`<!ENTITY>\`, internal subset, repeated declaration, oversized/ambiguous identifier or non-article DOCTYPE fails closed. XML relying on named custom entities may consequently still fail, which is intentional. This is compatibility work, not an XML security certification.

The article receipt now includes bounded **article type as deposited**, up to three *candidate* section headings under \`<body><sec><title>...\` that include the selected quotation, and a \`doctype_handling\` value (\`absent\` or \`simple-external-declaration-stripped\`). A nested section can cause more than one heading to match, and section labels can be incomplete or deceptive. The receipt explicitly sets \`section_context_is_support_verdict=false\` and \`claim_verified=false\`. No automatic assessment of study design, risk of bias, methods, sample adequacy, statistical quality, or scientific reproducibility occurs. All displayed fields are text-only; no article body is copied, persisted or rendered as markup.

Tests include a simple external JATS DTD that must be **removed before parsing**, internal entity/DTD and duplicate-declaration refusal, article type and source-provided section heading attribution, and a Chromium mock with real DOMParser. A separate \`scripts/probe-studio-europepmc-live-browser.py --live\` script is provided for an **explicit operator-run network smoke test**, not deterministic CI. It sends one chosen PMCID (default \`PMC7029759\`) through the actual NEXUS reader from a disposable file-origin Chromium page, prints only bounded receipt metadata or a failure code, and never stores full article text. A successful disposable-origin test would **not** certify a future production origin; run a separate production-origin check before launch. This browser CORS smoke check has not been proven successful in the current development environment, which lacks external name resolution. Do not represent mock tests as live integration success.

To run the optional probe from a checkout with Chromium installed:

\`\`\`bash
python3 scripts/probe-studio-europepmc-live-browser.py --live --pmcid PMC7029759
\`\`\`

A probe failure can mean lack of network/DNS, CORS differences, an article exceeding the strict caps, or changed XML structure; it must be investigated rather than automatically relaxed. The draft PR is not a deployment.

## Increment: publisher-deposited article identifiers and related-article notices (23 November 2026)

The consented Europe PMC JATS receipt additionally presents a **bounded article-level DOI** when it matches a conservative DOI syntax and has a single unambiguous value. Conflicting DOI values result in an explicit ambiguity warning, not a chosen identifier. The reader never searches a reference list to guess the article DOI. It also lists up to three publisher-deposited `related-article-type` values (such as `corrected-article`) as *untrusted orientation hints* only. These strings are inert text and are not interpreted as proof of correction, retraction, scientific reliability, or article identity. Their absence must never be presented as evidence that the article has not been retracted. The receipt explicitly states `retraction_status_verified=false` and `claim_verified=false`.

The feature reuses the same already-consented, bounded XML body: **no additional network request or third-party disclosure**. DOI metadata and related-article types may be incomplete, stale, malformed, misleading or publisher-deposited without independent attestation. It does not query a retraction registry, cross-check Crossref, certify the publisher or change the human's assessment. Synthetic Node and narrow/wide Chromium fixtures cover a single DOI, conflicting identifiers, publisher notice hints, inert output and non-authoritative state. The feature remains a stacked draft pending review and exact-head CI; it is **not deployed**.

## Increment: on-demand local comparison of Crossref and Europe PMC DOI receipts (23 November 2026)

After the reviewer independently requests and approves **both** the Crossref DOI metadata request and a Europe PMC JATS article lookup for the same selected claim, Studio enables a separate **Compare the two DOI records locally** button. No new request, DNS lookup, search, model operation or third-party disclosure occurs during comparison. The exact Crossref DOI is compared with the unambiguous, conservative article-level DOI deposited in the Europe PMC XML. The four mutually exclusive results are: identical deposited DOI strings; different deposited DOI strings; conflicting DOI declarations inside article XML; or no usable article DOI. These are **string comparison outcomes only**, not scientific verification, source authentication, publication equivalence, risk-of-bias scoring or retraction validation.

The pure comparator fails closed for malformed, cross-claim, wrong-origin, missing-hash, incomplete or forged-success receipt shapes. It never assumes a SHA-256 fingerprint authenticates a third party. Both original retrievals remain separately opt-in and have provider-specific CORS/privacy restrictions. A comparison is available only for two successful in-panel receipts. Re-fetching either source, changing the DOI/PMCID/quotation fields, closing the panel or switching the reply invalidates stale comparisons. Any changed input is revalidated **again on click**, including programmatic value changes that do not fire input events. The output is inert bilingual text, neither saved to chat/archive nor transmitted to a model. The operation has `network_requests=0`, `same_publication_verified=false`, `claim_verified=false`, `retraction_status_verified=false`, `authority=none`.

Synthetic Node tests cover all four outcomes and adversarial receipt tampering. Integrated Chromium tests cover explicit consent order, mismatch vs match, invalidation on edits, no extra network and absence of false claims. Production CORS/live provenance and independent research review remain unverified. This is a stacked **draft only**, never a public-release claim.

## Hardening: in-memory provenance of comparison receipts (23 November 2026)

Receipt-shaped JSON alone is not proof that a source lookup happened. The local Crossref and Europe PMC readers now register each successfully returned **frozen object instance** in separate closure-private `WeakSet` registries. The DOI comparator refuses clones, serialized/deserialized JSON, synthetic objects with correct fields and wrong-source receipts: both exact objects must have been issued by the corresponding consented reader in this page session. This strengthens a local API boundary, but it **does not** authenticate Crossref, Europe PMC, the publisher, the browser, or the underlying paper; a compromised page or hostile extension can still tamper with runtime behavior.

The registries are ephemeral, invisible in reports, and store no fetched article text or additional personal information. No new API calls, auto-export, model disclosure, persistent history, background job, or claim-verification inference is introduced. UI still clears and revalidates receipts on source edits and panel changes. Synthetic tests now mint separate genuine receipts for match / mismatch / missing DOI and reject even field-for-field frozen clones. Stacked draft only; exact-head checks and independent review remain prerequisites to merge or deployment.

### Bundle repair and verification boundary

During source-to-bundle inspection, the stacked parent branch's embedded claim-review script did not equal the reviewed source file: a literal JavaScript replacement token (`$&`) had inserted a duplicate script fragment into the generated HTML. In this branch, both `web/studio.html` and `public/studio/index.html` were repaired by replacing the entire affected script block with the **exact** reviewed source module, without JavaScript replacement-string interpolation. A direct audit found exact source-to-bundle identity for the other 29 reviewed modules except the special Office-ZIP helper composition, which needs its own build gate. The public HTML byte count, SHA-256 and offline cache package ID were recomputed against the corrected public bytes. The public file remains under its deliberate 695,000-byte cap.

A synthetic JavaScript runtime smoke check with mocked consented Crossref and Europe PMC responses confirmed that a genuine pair can be compared and field-identical cloned objects are refused. This does not replace running `node scripts/test-studio-claim-review.mjs`, `python3 scripts/build-studio.py --check`, `python3 scripts/build-studio-static.py --check`, Chromium tests, exact-head CI, or independent reviewer approval. No physical-device or production-origin CORS verification has been run, and these changes have not been merged/deployed.
