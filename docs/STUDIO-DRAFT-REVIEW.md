# Studio structural draft review and bounded bundle compaction

Development candidate, not a public deployment. Before appending a model response to the conversation, the existing reply-format module reviews the exact returned text locally. It flags a provider-reported length limit, whitespace-only content, unusual control characters, unclosed Markdown fences, and exact repeated paragraphs of at least 100 normalized characters outside fenced code. Structural inspection is bounded to 100,000 characters. An empty response is rejected with the original user draft preserved; other findings are advisory status messages, not silent rewrites or retries. The response remains exactly as returned (apart from the existing on-device label). No model request, new permission, storage schema or external service is added. This is not factual verification, intent understanding, semantic reasoning, or a guarantee of answer quality; repeated material and literal formatting may be intentional. Streamed preview behavior is unchanged: inspection occurs on completion before committing the final reply, not before streaming.

The standalone builder removes only whole-line comments from the eight reviewed lexical review modules when no template literal, block comment marker or escaped newline appears. All line breaks and original source files are retained. Other modules are unchanged. The previous public index was 640,672 bytes; the new index is 637,572 bytes, including structural review. 5,189 comment bytes were removed, net reduction 3,100 bytes, ceiling remains 650,000 bytes. No dependency or capability removed. Native deterministic build, browser witness and exact-head CI must pass before promotion.

Tests: scripts/test-studio-draft-review.mjs (20 synthetic checks); scripts/test-studio-model-receipt-browser.py (empty response, advisory warnings, no rewrite/no extra request). The former was exercised in an isolated JS environment; the new browser assertions have not been run here. No factual or public-release claims.

## Explicit second-pass answer review (development candidate)

The latest model answer in a non-archived conversation has a **Review answer with model** action. It preserves existing drafts and prepares an editable English or Persian request asking the configured model to compare its immediately preceding answer with the original request, identify unmet requirements, unsupported claims, contradictions and assumptions, distinguish uncertainty, and suggest corrections when needed. If no model is configured the draft remains available. The unchanged review prompt requires the exact complete original user turn and model answer in the prepared context; missing or altered context blocks preparation. Editing the prompt makes it an ordinary user request. Prior file excerpts may no longer be available and the prompt explicitly asks the model to disclose missing context. The existing exact-request consent gate remains mandatory, including any privacy warning; clicking review never sends a provider request. On approval this is a normal new conversation turn, potentially incurring provider usage, not a silent retry or replacement of the original answer. Model critique is not independent factual verification or guaranteed semantic accuracy. 21 synthetic context checks passed in JS isolation; browser acceptance assertions and CI invocation added but not executed here. Public index 640,879 bytes, below unchanged 650,000-byte cap. No public deployment.

## Request-local reference audit (development candidate)

Actually included project source and one-turn file excerpts receive distinct S1... and A1... identifiers in the reviewed request. Optional context omitted by the budget receives no identifier in the request's reference inventory. The response review recognizes exact [NXS:S1] / [NXS:A1] markers and reports matching, unknown, absent, or scan-limited markers locally at response completion. The response is preserved, with no automatic retry, rewrite, provider call, external research or new persistence. Names and line numbers remain visible in the request review. Matching an identifier only means that identifier was supplied for this request; it does not establish claim support, correct quotation, source quality, causality or truth. References in quoted examples or code may also be matched; plain citations or malformed markers are not assessed. The identifiers are per request, not global; the status is transient and is not evidence retained in conversation history. 25 synthetic marker/context checks passed in isolated JS; native CI and browser verification are pending. Public index 643,008 bytes (650,000-byte cap unchanged). No public release.

## Claim evidence and uncertainty review (chat candidate)

The new pure module `studio-evidence-review.mjs` reviews bounded structured claim/quote judgments against the actual request-local passages. It checks exact substring presence and known references, groups normalized identical excerpts, flags reused quotes across different excerpts, partial passages and single-file reliance, and distinguishes reported support, contradiction, conflicting reports, uncertain judgments and opposing interpretations of the same excerpt. Invalid references take precedence and require reconciliation. Stances are supplied explicitly; this module does not infer them from text. File and excerpt counts are not counts of independent evidence; copied material across different surrounding passages may still be counted as distinct excerpts and is only flagged. It does not rank source quality, verify authorship or chronology, establish entailment or truth, resolve conflicts, store quotes, contact a provider or authorize action. The output contains only claim IDs, references, statuses, counts and flags, no raw passage or quote. Off/isolated mode does not inspect inputs. Limits: up to 10 passages, 20 claims, 80 judgments. 44 synthetic checks passed in isolated JavaScript; native CI invocation added. The module is now bundled and mounted as a collapsed Review evidence panel below the latest completed ordinary model reply when request-local excerpts were actually supplied. The panel accepts one exact claim substring and up to two exact quotations plus explicit human judgments. Excerpt text is transient in the current tab; it is not retained in the conversation/archive or sent to the model by this panel. Isolated chats have no evidence panel. Draft changes or other stop/re-render events discard the panel; it cannot be reopened from history. Engine result codes remain in English, while form labels are bilingual. This is not automatic semantic assessment. The builder additionally removes leading horizontal whitespace only in the previously reviewed lexical modules without template literals, block-comment markers or escaped newlines, preserving line breaks and original sources. Public index 649,909 bytes (91 bytes remaining under 650,000-byte ceiling). 7 additional context checks passed in JS isolation; new browser assertions added, not executed here. Native full deterministic build and exact-head CI/browser acceptance remain required. No public release.
