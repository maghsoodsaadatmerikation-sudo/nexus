# NEXUS v1.3 Roadmap — Authority-Preserving Production Hardening

Status: ACTIVE / UNSEALED

NEXUS v1.3 begins after the immutable v1.2.0 operational-resilience seal. It must not rewrite v1.0.0, v1.1.0, or v1.2.0 evidence or tags.

## Constitutional invariant

`A_out <= A_in`

Production hardening may reduce failure probability and improve observability, but it must not create new epistemic authority, release authority, or authorization semantics.

## Goal

Make the sealed NEXUS runtime easier to operate safely by turning security, provenance, failure behavior, and release-boundary drift into explicit fail-closed verification gates, without requiring paid infrastructure.

## Gates

### G1 — Historical seal integrity
- `v1.2.0` must resolve to `fbe17b80206df5e63f7351cc97f1794eb8c88e17`.
- v1.2 verification run `34848797043` remains the sealed candidate evidence.
- Historical evidence is read-only; v1.3 evidence is additive.

### G2 — Gateway authority non-expansion
- Gateway remains limited to parse / validate / envelope / delegate / serialize.
- No gateway-local authorization, denial policy, interpretation, or authority mutation may be introduced.
- Existing constitutional-core boundary tests remain required.

### G3 — Secret and evidence hygiene
- Verification artifacts and release manifests must contain no bearer token or secret value.
- Evidence records identifiers/digests, never authentication material.
- Secret absence checks fail closed.

### G4 — Provenance and dependency integrity
- Cargo.lock remains pinned and verified.
- CI actions and verification container references remain immutable/pinned.
- Release candidate records exact commit and verification run.

### G5 — Failure transparency
- Verification failure must block candidate readiness.
- Scheduled verification may observe, verify, attest, and report only; it has no release authority.
- No automatic repair may mutate production data or authorization state.

### G6 — Operational economy
- No paid resource upgrade is part of this roadmap.
- Existing durable `/data` boundary is preserved.
- Progression must stop rather than silently incur cost.

### G7 — v1.3 release-candidate gate
- G1–G6 must PASS on one exact candidate commit.
- Full NEXUS Verification must complete successfully on that exact commit.
- Publication remains a separate human-authorized action.

## Scope boundary

v1.3 is production hardening, not a claim of formal proof, universal availability, universal security, or epistemic correctness. Provider behavior outside observed evidence remains outside the seal.
