# DOCX privacy inventory and bounded copy

Authenticated POST /studio/api/documents/privacy/review and /run accept base64 DOCX up to 2 MiB compressed, 8 MiB expanded, 128 entries and 2 MiB per entry; UTF-8 XML only, no extraction to disk. Rejects ambiguous paths, case-insensitive duplicates, encrypted/unsupported entries and DTD/entity declarations. Review returns counts, not identity values or filenames, for core/other properties, comments, revisions, hidden-text markers, identity attributes, external relationships, custom XML, headers/footers, media/embedded parts and ZIP metadata. These are limited heuristics. Explicit reset_core_properties replaces the conventional docProps/core.xml with an empty core-property element (including legitimate title and keywords); reset_zip_metadata rebuilds entry timestamps/comments/extra fields and archive comment. Run requires exact digest and consent, refuses detected signature/macro packages, creates a new base64 copy and reinspects it. Core-only reset refuses archive comments unless ZIP reset also approved. Other package parts remain byte-identical; ZIP container encoding may change. No semantic redaction, removal of tracked changes/comments, embedded/media inspection, PDF support, OOXML conformance or rendering assurance, external calls, storage or browser integration. Not a guarantee of anonymity, nor a production-ready file sanitizer. Exact-head CI required.
