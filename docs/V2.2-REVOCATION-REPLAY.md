# NEXUS v2.2 — Revocation Replay Integrity

Status: ENGINEERING CONTRACT / NOT SEALED

## Claim

v2.2 makes capability revocation state reconstructible from an ordered, provenance-bearing event history and rejects malformed replay fail-closed.

It does **not** claim cryptographic authenticity, distributed consensus, durable storage by itself, external federation, provider correctness, or universal security.

## Constitutional invariants

- `A_child <= A_parent <= A_in` remains unchanged.
- Revocation can only reduce future delegated execution; it cannot mint, widen, repair, or restore authority.
- Evidence is not authority.
- A replayed revocation history must be structurally valid before it can participate in authorization.
- Duplicate grant revocation is idempotent in effective state but remains an observable append-only event.
- Unsupported schema, broken sequence, empty grant identity, or empty provenance fail closed.

## Data contract

`RevocationEvent` contains:
- monotonically contiguous `sequence`
- non-empty `grant_id`
- non-empty `provenance_id`

`RevocationSnapshot` contains:
- exact schema version
- ordered events only

Effective revoked state is reconstructed from events; it is not trusted as an independent mutable field.

## Authorization boundary

`PolicyEngine::authorize_delegated` continues to consume only a validated `RevocationSet`. A snapshot must first pass `RevocationSet::from_snapshot`; malformed snapshots cannot construct a revocation set and therefore cannot silently authorize through replay.

## Required negative tests

- unsupported revocation schema fails closed
- broken sequence fails closed
- empty grant id fails closed
- empty provenance fails closed
- replay reconstructs revoked grants
- repeated revocation remains revoked
- revocation cannot expand authority

## Release rule

No real verification -> no PASS -> no seal.

A v2.2 release requires exact-candidate canonical NEXUS Verification plus v2.2-specific evidence. v2.1 remains an immutable prior seal.
