# NEXUS v2.6 — Bounded Storage Failure & Request Continuity

**Status: CANDIDATE / UNSEALED**

## Exact boundary (to be sealed)

- Request marker reservation is synced before constitutional delegation.
- Interrupted or torn reservation recovers as `Indeterminate`, never `Accepted` or `Pending`.
- Storage failure (including ENOSPC) fails closed before delegation.
- Transport authentication and constitutional authority remain separate.
- Invariant: `A_out <= A_in`.

## Verified claims (target)

- `RequestStore::reserve` writes a non-accepted prefix and `sync_all`s before any delegate boundary.
- Crash or process kill after reservation recovers the marker as `Indeterminate`.
- A torn `pending` write also recovers as `Indeterminate`, never as accepted.
- Storage capacity failure during reservation fails closed and does not cross into constitutional execution.
- Existing authenticated transport admission (v2.5) is preserved; no new authority is created.

## Explicit non-claims

This boundary does not claim:

- distributed or multi-host persistence
- consensus or linearizability across nodes
- cryptographic authenticity of markers
- power-loss durability beyond process crash and fsync of the marker path
- automatic recovery of accepted requests
- universal storage health or unlimited disk

## Relation to prior seals

v2.5 remains the immutable unified transport-authentication boundary. v2.6 does not rewrite it. Later seals must establish their own exact-commit verification and evidence.

## Completion rule

No real verification -> no PASS -> no seal.
