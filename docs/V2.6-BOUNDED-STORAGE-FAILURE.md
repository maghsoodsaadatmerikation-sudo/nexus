# Request continuity under bounded storage failure

Status: ENGINEERING CANDIDATE / UNSEALED

This independent witness executes existing gateway tests with an immutable Rust
container image and both pinned Cargo.lock files. It does not change runtime
code, grant release intent, create a tag, attest a bundle or publish a Seal.

## Executed checks

Run `bash scripts/v2.6-request-continuity-verification.sh` on a disposable Linux
CI host with Docker. The script mounts only the checkout, never operator data.

- The process-crash test waits for a synced request reservation, kills its child,
  reopens the marker store and requires Indeterminate plus duplicate rejection.
- The explicit ignored ENOSPC test runs on a private 8 MiB tmpfs and checks that
  capacity failure prevents delegation. Ordinary filtered cargo tests omit this
  ignored test; the witness explicitly uses `--ignored --exact`.
- Both invocations must report the named test and exactly one passed, zero failed
  and zero ignored tests. A missing or renamed test cannot silently pass.

The read-only workflow runs on pull requests and main and uploads unsigned
engineering evidence only after both checks succeed. Its manifest binds the
executed commit/run/image; separate root and gateway lockfiles and witness logs
are included. The SHA-256 inventory detects inconsistent bytes, not authenticity.
Only actual workflow execution establishes these narrow PASS claims.

## Limits and authority

The canonical Verify remains required for CT-001..020, self-audit, transport
authentication, torn-marker behavior and the full live HTTP/recovery contract.
This witness does not prove distributed persistence, consensus, power-loss
durability, cryptographic marker authenticity, zero-loss recovery, executor
completion, provider health or restored production data. Pending means accepted,
not completed; interrupted reservations remain indeterminate.

`A_out <= A_in`, evidence != authority and the AuthorizedRequest boundary remain
mandatory. Bootstrap prepares fixtures; it does not establish verification PASS.
No successful witness or artifact grants permission to resume a quarantined
installation. v2.5.0 remains the immutable published transport boundary. Any new
Seal requires separately authorized release intent and exact-candidate review.
