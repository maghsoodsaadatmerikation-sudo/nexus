# Review-only model orchestration

Authenticated POST /studio-api/model-plan previews one to three distinct configured routes with the same caller-supplied messages, optional context selection, presentation and creative profiles, mode, output allowance and streaming flag. All requested routes must be compatible; no automatic fallback. The existing provider payload builder is shared with the completion paths. The response contains route identities, included/omitted message counts, a request-review HMAC per route and the observed local request budget. No raw prompt, key, provider payload or upstream answer is returned. Preview never contacts a provider, reserves budget or authorizes execution.

For each intended separate /studio-api/respond or /studio-api/respond-stream call, the client may supply request_review_id from the preview alongside the same context, route configuration_id and explicit consent. The server recomputes the HMAC using the frozen route, exact provider payload and current credential; mismatch rejects before budget reservation. Omission retains legacy behavior. The ID binds the outbound payload (not omitted messages or equivalent input representations), is not single-use, not an authorization token or proof of human review. The observed budget is neither reserved nor a monetary cap; concurrency can change it. Existing per-call authentication, consent, configuration, budget and provider policy remain authoritative. No automatic multi-call dispatch, consensus synthesis, quality ranking, retry, live provider test, persistence or browser controls. Tests use mock transport. Exact-head CI required.
