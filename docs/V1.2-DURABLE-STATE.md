# NEXUS v1.2 G3 — Durable-State Resilience

Status: DEVELOPMENT / UNSEALED

This gate turns the existing persistence and recovery behavior into an explicit v1.2 operational contract. It does not create release authority and it does not replace the sealed v1.1.0 durable-host evidence.

## Boundary

The runtime persistence boundary remains `/data`.

Operator backup/export is scoped to one explicitly selected workspace and uses the authenticated workspace API. Exported JSON is validated before it is accepted as a backup artifact. Restore is sent back through `/v1/workspaces/import`, where NEXUS revalidates the snapshot before persistence.

The bearer token is transport authorization only. It must not be written into backup artifacts, release evidence, logs, or repository files.

## Destructive testing rule

Destructive recovery validation may only operate on a dedicated synthetic witness. CI uses an isolated temporary directory under `RUNNER_TEMP`, destroys that temporary witness state, restores from the captured JSON snapshot, checks JSON-equivalence, restarts again, and verifies the restored witness remains readable.

Production user data must never be used as the destructive witness for this gate.

## Gate

Run:

```bash
bash scripts/v1.2-durable-state-resilience.sh
```

The gate fails closed if the `/data` boundary, backup/restore validation, isolated witness destruction, JSON-equivalent restore assertion, or secret-leak guard is removed.

A PASS from this gate establishes only that the repository still contains and exercises the defined resilience controls. It is not a universal disaster-recovery guarantee and does not expand epistemic or execution authority.
