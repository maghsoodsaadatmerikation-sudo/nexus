# Explicit provider context selection

The existing completion gateway accepts optional context_selection.indices, a strictly typed ascending unique list of zero-based message positions. The final user message is mandatory. Earlier selected messages must form complete adjacent user/assistant pairs in the original request. No gap is treated as a complete turn. Choosing only the final index forwards only the latest user message plus the fixed server policy and explicit response profile. The gateway adds a fixed omitted-context notice when necessary; no omitted text or automatic summary is forwarded. Invalid selections fail before budget reservation or provider contact. Both buffered and streaming routes share the same code. Omission preserves legacy behavior exactly.

This is explicit outbound provider minimization, not minimization of data sent to the NEXUS gateway: all submitted messages still reach the gateway and count toward existing transport limits. A browser client should avoid sending unnecessary data in the first place. Optional project context in the current browser is a separate leading user message and is not automatically preserved by the new selection. No memory retrieval, semantic ranking, redaction within selected messages, hidden storage, independent consent evidence, UI controls or live model compliance guarantee is added. Existing configuration review and consent still apply. Tests check mock provider wire contents and rejection; exact-head CI required.
