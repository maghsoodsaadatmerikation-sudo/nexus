# NEXUS v2.4 — Gateway Authority-Confusion Defense

## Claim

Artifact 05 accepts only the exact constitutional request schema. Transport metadata is evidence of client input, never authority.

## Boundary

- valid exact-schema requests retain `POST /v1/requests -> 202 Accepted`;
- unknown fields fail with `422 Unprocessable Entity` before delegation;
- authority-like fields including `capability`, `grant`, `revocation_epoch`, `authorized`, and `policy` fail closed;
- the Gateway exposes no capability mint, revocation, authorization, or policy mutation route;
- `GET /v1/requests/{id}` remains transport status only and returns `404` when unknown.

## Independent verification

The v2.4 verification script runs the locked Artifact 05 test suite and requires explicit negative tests proving that ambiguous input never reaches `ConstitutionalDelegate`.

## Non-claims

This boundary does not claim that HTTP authenticates authority, that the Gateway authorizes requests, that external clients are trustworthy, or that transport validation provides cryptographic authenticity. It does not add durable/distributed persistence, consensus, federation, production mutation, or external-system linearizability.

## Authority invariant

`A_out <= A_in`. Rejected or ignored metadata cannot mint authority. Evidence remains distinct from authorization and release authority.
