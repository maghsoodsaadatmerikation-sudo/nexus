# NEXUS v1.2 G5 — Release Gate

Status: IMPLEMENTED / UNSEALED

## Boundary

G5 packages the v1.2 operational-resilience gates into a release-candidate record. It does not create a tag or GitHub Release and it does not infer that a GitHub Actions run succeeded merely because a run ID exists.

The invariant remains:

`A_out <= A_in`

## Preconditions

A v1.2 release candidate requires:

- G1 release-boundary integrity: PASS;
- G2 continuous verification: PASS;
- G3 durable-state resilience: PASS;
- G4 operational economy: PASS;
- exact candidate commit represented by a full 40-character SHA;
- an external NEXUS Verification run ID for that exact candidate commit;
- no authority expansion;
- no secret material in the candidate manifest.

## External verification rule

The generated candidate manifest MUST contain:

`Verification Run Independently Checked: NO`

until a human/operator independently checks GitHub Actions and confirms that the referenced run completed with `success` for the exact candidate commit. A numeric run ID alone is not evidence of success.

## Release action boundary

The candidate manifest MUST also contain:

- `Release Action Performed: NO`
- `Tag Created: NO`
- `GitHub Release Published: NO`

The `v1.2.0` tag and GitHub Release may be created only after the exact candidate run is independently confirmed successful and the repository owner gives an explicit human release decision.

## Epistemic scope

G5 is an operational release-readiness gate. It does not claim formal epistemic correctness, universal availability, or provider-wide billing guarantees.
