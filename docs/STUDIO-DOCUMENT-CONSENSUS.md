# Document critique comparison

Each successful document critique now includes a compact HMAC receipt binding configured slot, request review, normalized actual system/user messages and token cap, critique result tag and ordered reported verdicts. Authenticated POST /studio/api/documents/critique/comparison compares two or three distinct slots with identical context, validates receipt signatures and coverage, and reports unanimity/disagreement plus opposing or insufficient verdicts per statement. No new provider call, no automatic routing or majority vote. Different slots may use the same model or provider; shared operator token holders can forge receipts and replay is allowed. No independent provenance, truth, semantic agreement or confidence verification. The original critique contains rationale and source citations; comparison is categorical only. Mock provider tests and exact-head CI required. No UI or live deployment.
