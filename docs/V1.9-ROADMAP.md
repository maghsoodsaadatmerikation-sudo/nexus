# NEXUS v1.9 — Runtime Drift Detection & Non-Authoritative Production Watch

Status: **DEVELOPMENT / UNSEALED**

## Engineering claim

v1.9 adds fail-closed, read-only detection of drift between the sealed production runtime identity and later public runtime observations. Observation never becomes authorization.

Constitutional invariant: `A_out <= A_in`.

## Why this boundary follows v1.8

v1.7 sealed runtime provenance and v1.8 sealed reproducible executable identity across two independent builders. Both are point-in-time evidence. The remaining narrow operational gap is temporal: later production drift must be detectable without granting a watcher deployment, rollback, promotion, policy, or judgment authority.

## Gates

### G1 — Historical integrity
- v1.8.0 remains immutable.
- v1.7 production runtime digest remains the production reference until an independently authorized promotion changes it.

### G2 — Read-only public observation
- A scheduled/manual workflow queries only the public `/v1/runtime-identity` endpoint.
- It checks HTTP 200, schema `nexus.runtime-identity.v1`, authority `non_authoritative_build_metadata`, and exact expected source-tree SHA-256.
- Mismatch, malformed output, unavailable identity, or unexpected authority fails closed.

### G3 — Evidence provenance
- Every successful observation emits JSON evidence plus SHA-256.
- Expected and observed identities remain separate fields.
- Evidence is attested and uploaded.

### G4 — Authority non-expansion
- No Railway credential or NEXUS bearer token is available to the watcher.
- The watcher cannot deploy, promote, rollback, authorize requests, create HumanJudgment, mutate policy, or write production state.

### G5 — Economy
- No new Railway service, volume, paid upgrade, or continuously running helper.
- Existing GitHub Actions infrastructure only.

### G6 — Release boundary
- Exact candidate must pass NEXUS Verification.
- The drift watcher must make at least one real successful public observation before a v1.9 seal can be considered.
- A seal may claim only read-only temporal drift detection at the stated observation boundary.

## Non-claims

v1.9 is not intrusion detection, autonomous remediation, formal provider verification, universal availability, universal security, or formal epistemic proof.

## Completion rule

No real observation -> no PASS. No exact-candidate verification -> no seal.
