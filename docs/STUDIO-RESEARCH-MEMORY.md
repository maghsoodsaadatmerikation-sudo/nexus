# Portable research memory

The operator-authenticated research/memory/change and research/memory/recall endpoints operate only on caller-supplied snapshots. A snapshot contains one project ID, a revision and up to 30 explicitly authored notes (500 characters each), each referencing a research draft digest and one to six claim IDs. Changes require strict consent, matching project ID and exact snapshot digest. Add recomputes the original critique and validates the reference digest and claim membership; the note itself is not verified or entailed. Remove and clear return a new snapshot without the selected records. The old input and any backups are not erased. There is no server-side persistence, global revision authority, cross-device sync, cryptographic signature or protection against replay/forked snapshots; the caller must manage the current snapshot and securely store or discard it. Imported snapshots and their digests do not authenticate historical provenance. Project IDs are consistency labels, not authorization boundaries.

Recall defaults off, isolation overrides opt-in, and returns only matching record IDs, lexical overlap counts and reference identifiers. Basic Unicode normalization includes Persian Arabic letter variants. No embeddings, automatic note extraction, model invocation, raw excerpt retention, automatic context injection, external requests or browser integration. The existing encrypted browser archive is unchanged. No claim of encrypted transport, logging exclusion, permanent deletion or semantic relevance beyond the existing gateway configuration. Exact-head CI and integration review required.
