# Analysis Artifact Engine — bounded export candidate

The operator-authenticated POST /studio/api/analysis-batch/export accepts an existing ApprovedBatch, format json/csv/html/xlsx/docx/pdf/pptx/svg, and strict explicit export_consent. It recomputes the batch and requires the consistency audit to pass before building any attachment. A mismatch returns 409 with no file. A fresh calculation is performed, not a caller-supplied result. The file records metrics and input provenance, not original text, numeric arrays, descriptions or goal. Derived metrics and digests can still be sensitive. Consent is caller-reported, not independently witnessed.

JSON preserves structured metrics; CSV uses stable metric/provenance rows with only fixed enums, validated letter-first step IDs, and numbers; HTML is escaped static markup with no active content or external resources. Downloads have a fixed filename, no-store, nosniff, restrictive CSP and SHA-256 of the actual bytes (integrity identifier, not a signature). Maximum request 64 KiB, file 128 KiB. No persistence, external tools, new dependencies, UI integration or cloud storage. Existing browser Word and other exports are not replaced. XLSX provides typed numeric cells and separate report/metadata sheets; DOCX provides a landscape report table and repeated header. Both are minimal deterministic Open XML packages built with the Python standard library, no external relationships, macros or formula cells. Tests inspect ZIP/XML structure; independent Office application rendering/interoperability is not yet verified. PDF uses a paginated ASCII report with standard Helvetica and explicit cross-reference offsets. PPTX uses editable text shapes, a blank layout/master/theme and paginated report rows. No raw prose, external relationships or active content. Both are minimal standard-library generators for the fixed analysis schema, not general document design or arbitrary Unicode publishing. Structural tests do not establish visual layout or application compatibility. Public multi-user authorization and deployment remain separate work. Tests must pass on the exact commit.

SVG export requires explicit chart_metric (one existing metric). It generates a static signed horizontal bar chart for the matching steps, including a zero baseline, exact value labels, and reviewed digest. The user must ensure compared metrics have compatible units; the engine has no unit metadata. Missing metrics are omitted and no-match requests fail. No automatic choice, scripts, external resources, raw prose, PNG rendering or interactive dashboards. The same consistency and consent gates apply. Structural and signed-bar tests are added; independent visual QA remains pending.
