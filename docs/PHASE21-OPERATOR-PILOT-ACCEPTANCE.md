# Phase 21 — usable local operator pilot, no deployment

## Why this matters

Phase 20 CI passed but did not provide a single repeatable local acceptance
entrypoint for a human operator. NEXUS now offers **two distinct operations**
that preserve \`A_out <= A_in\`:

1. A **preflight snapshot** checks the existing 0700 operator root, private
   journal ledger and quarantine indicators, optionally verifying that an
   explicitly named workspace already exists. With \`--inspect-docker\`, it
   also observes labelled containers through the existing read-only Docker
   inventory. The report never calls this host production-safe or absence
   of labelled containers proof of absence of orphans.
2. An **explicit disposable smoke test** exercises the real private Unix socket,
   owner token, inert review, a bounded fixed two-step plan (verify synthetic
   file hash, write synthetic result), durable one-use journal, terminal receipt
   and replay denial. All content, outbox and credentials live in a fresh
   temporary 0700 directory removed on exit. No user project, container, model,
   Docker daemon, network, hosted service, or public API is involved.

## Commands

On a **nonroot Linux** machine with Python 3.13 and the NEXUS source:

~~~bash
python scripts/nexus-operator-pilot.py check \
  --root /absolute/private/operator-root --workspace alpha
python scripts/nexus-operator-pilot.py check \
  --root /absolute/private/operator-root --workspace alpha --inspect-docker
python scripts/nexus-operator-pilot.py smoke --approve-disposable
~~~

\`check\` is not fully filesystem-write-free: taking the private admission
flock can create a persistent owner-only metadata lock file in the root.
It never creates a workspace or a new approval. A clean observation returns
\`preflight-clear-not-attested\`, still \`production_ready=false\`,
\`host_attested=false\` and \`orphaned_processes_ruled_out=false\`. Blocked or
unverifiable checks exit code 2. Even a clean snapshot cannot reserve future
admission or attest another Docker daemon.

\`smoke\` requires the literal \`--approve-disposable\` flag; it is **not**
a general-purpose executor. It supplies one known synthetic plan using the
existing operator-only server, checks source and final receipt, then destroys
its disposable root. It deliberately does **not** test Docker or Linux
namespace isolation; the separate CI jobs are responsible for those. No plan
generated by a model is used or authorized, and there is no browser bridge.

## Verification and next release gate

The new tests cover no implicit smoke consent, missing workspace not created,
durable incomplete journals blocking check, cleanup uncertainty, Docker
unverifiable/empty observations, real Unix-socket execution, journal receipt
and replay denial, and redaction. A dedicated GitHub Actions job runs the
smoke program on ephemeral Ubuntu without write permissions, secrets, Docker,
sudo or network configuration changes.

Passing is evidence of **local single-operator workflow acceptance**, not
public installability, persistence across hosts, permission to run arbitrary
AI code, or production security. Promotion must still be a separate human
decision after live host and recovery evidence; PR #244 remains Draft.
