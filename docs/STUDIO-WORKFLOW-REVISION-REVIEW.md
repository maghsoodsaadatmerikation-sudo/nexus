# Workflow revision review

The operator-authenticated revision-review endpoint compares a caller-supplied previous plan/progress and a proposed replacement. It checks original digest and dependency validity, identifies additions/removals/changes, propagates affected steps through the proposed dependency graph, and invalidates all prior acknowledgments on a goal change. Unchanged unaffected acknowledgments are suggestions for re-review only; no acknowledgment is carried automatically. A cancelled plan is not revised in place. A new plan digest is returned and no execution authority is granted.

This is deterministic impact analysis, not autonomous replanning or generation of a replacement. The caller supplies the proposal. The old progress is caller-reported, not durable checkpoint evidence. Descriptions cannot establish semantic equivalence, and changes outside the plan (tool inputs, permissions, source data, provider state) are not covered. No queue/checkpoint mutation, external operation or Studio UI is added. New revisions need fresh review and eventual explicit storage integration. Request size is capped at 64 KiB. Exact-head CI and deployment review remain required.
