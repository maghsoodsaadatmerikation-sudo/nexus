# NEXUS v1.4 Release Gate — Deployment Truth & Evidence Reconciliation

Status: **UNSEALED**

A v1.4 candidate is eligible for release publication only when all conditions below are satisfied.

## Required conditions

1. `scripts/v1.4-deployment-truth.sh` passes fail-closed on the exact candidate commit.
2. `evidence/live-deployment-state.json` is valid JSON, contains no authentication material, and records a provider-observed live deployment identity.
3. The v1.3.0 tag resolves to `458260fcadc95b53d5e33fa2fabf806519a8cccd`.
4. The live/release relationship is explicitly classified as one of `MATCHES_RELEASE`, `LIVE_BEHIND_RELEASE`, or `DIVERGED_OR_UNKNOWN`.
5. A `LIVE_BEHIND_RELEASE` or `DIVERGED_OR_UNKNOWN` state must never be rewritten as `MATCHES_RELEASE` without new provider-side evidence.
6. The exact candidate commit has a completed successful `NEXUS Verification` run.
7. No paid resource upgrade is required or authorized by this release gate.
8. Release publication does not imply production promotion.
9. Authority expansion remains `NONE` and the invariant `A_out <= A_in` remains intact.

## Separation of claims

- **Released** means a Git tag/GitHub Release exists at a verified commit.
- **Verified** means the exact commit passed the stated workflow and evidence gates.
- **Observed live** means provider-side evidence identifies a production deployment commit.

These statements are not interchangeable.

## Human boundary

Publication of a v1.4 release requires explicit human authorization. Production promotion is a separate operation and is not authorized by the release workflow.
