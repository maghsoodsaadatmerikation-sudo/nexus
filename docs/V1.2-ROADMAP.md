# NEXUS v1.2 Roadmap — Operational Resilience

Status: COMPLETE / SEALED

NEXUS v1.2.0 is the current sealed operational-resilience release boundary. It builds on, but does not rewrite, the immutable v1.1.0 durable-host evidence boundary.

## Constitutional invariant

`A_out <= A_in`

Operational automation may observe, verify, preserve evidence, and report failures. It must not silently expand epistemic or execution authority.

## Goal

Turn the v1.1 durable deployment proof into a maintainable operational posture without introducing paid infrastructure as a requirement.

## Gates

### G1 — Release-boundary integrity — PASS
- v1.1.0 tag/release boundary remains fixed.
- Referenced evidence identifiers and hashes are checked fail-closed.

### G2 — Continuous verification — PASS
- Deterministic CI verification runs on source changes.
- Scheduled verification runs at 00:00, 08:00, and 16:00 UTC.
- Scheduled checks verify/attest evidence only and have no release authority.

### G3 — Durable-state resilience — PASS
- `/data` remains the runtime persistence boundary.
- Backup/export remains authenticated and secret-free.
- Restore validation uses a dedicated witness; destructive CI tests do not target user data.

### G4 — Operational economy — PASS
- Auxiliary evidence/operator services are non-production helpers with restart policy `NEVER` and sleeping enabled.
- No paid resource upgrade was requested or performed for v1.2.
- The available Railway action rejects literal zero replicas, so v1.2 does not claim provider-side zero replicas.
- If a future progression requires paid resources beyond existing included resources, progression stops rather than silently incurring cost.
