# Review-bound reply comparison

Successful buffered model calls with a validated request_review_id now return an optional comparison_receipt. It contains the slot and configuration, reviewed request ID, HMAC of common outbound context and requested mode/output limit, exact SHA-256 of reply text, truncation flag and HMAC over these fields. The common context normalizes the existing Anthropic and Chat Completions wire envelopes; omitted input is not bound. Legacy calls without review ID and streaming replies are unchanged.

Authenticated POST /studio-api/model-comparison takes two or three receipts from distinct slots, verifies the tags with the current Studio token and requires the same context ID. It reports exact text match, different text or incomplete response for each pair. No raw reply, prompt, provider secret or additional provider request is needed. This is exact textual comparison, NOT semantic agreement, independent provenance, factual validation, majority voting or automatic synthesis. Holders of the shared Studio token can manufacture HMACs; these tags are consistency checks, not signatures proving remote model authorship. Distinct slots need not represent independent models. Receipt replay is allowed and comparison does not grant authority. Token rotation invalidates old tags. No automatic dispatch, budget consumption, storage or UI wiring. Mock transport and exact-head CI required.
