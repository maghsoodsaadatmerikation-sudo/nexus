# NEXUS v1.4 Roadmap — Deployment Truth & Evidence Reconciliation

Status: **DEVELOPMENT / UNSEALED**

NEXUS v1.4 follows the sealed v1.3.0 production-hardening boundary. It does not rewrite prior release tags or evidence.

## Constitutional invariant

`A_out <= A_in`

A release, a deployment, and an observed live state are different epistemic objects. Automation may compare them and report drift, but it may not silently collapse them into one claim.

## Goal

Make deployment truth explicit and machine-checkable so NEXUS never implies that the newest sealed release is the code currently running in production unless provider-side evidence supports that claim.

## Gates

### G1 — Historical seal integrity
- `v1.3.0` must remain fixed to its sealed candidate commit.
- The v1.3 release record remains historical and additive-only.

### G2 — Live deployment attestation
- Maintain a secret-free provider observation describing the currently observed production deployment.
- Record provider, service, deployment identifier, deployed commit, observation time, deployment status, durable-data mount, and authority claim.
- Authentication material must never appear in the attestation.

### G3 — Release/deployment reconciliation
- Compare the live deployed commit with the latest sealed release commit.
- `MATCHES_RELEASE`, `LIVE_BEHIND_RELEASE`, and `DIVERGED_OR_UNKNOWN` are distinct outcomes.
- A behind or divergent deployment is not automatically a failure; misreporting it as current is a failure.

### G4 — Claim discipline
- Repository documentation must not call a release "deployed" without provider-side evidence.
- Verification output must distinguish `released`, `verified`, and `observed-live`.
- No deployment action is authorized by this gate.

### G5 — Durable-boundary continuity
- `/data` remains the production persistence boundary.
- Reconciliation must not mutate or probe user data destructively.
- Evidence collection is read-only with respect to production state.

### G6 — Operational economy
- No paid resource upgrade is required or authorized.
- Auxiliary helpers remain outside the production authority path and should not be kept alive solely for evidence generation.

### G7 — v1.4 release gate
- Exact candidate commit must pass the full NEXUS Verification workflow.
- Deployment-truth evidence must be syntactically valid, secret-free, and internally consistent.
- Release publication does not imply production promotion.
- Production promotion remains a separate, explicit operator action with new provider evidence.
