# NEXUS v1.8 Roadmap — Independent Rebuild Reproducibility

Status: **DEVELOPMENT / UNSEALED**

NEXUS v1.8 follows the sealed v1.7.0 runtime-provenance boundary. v1.7 proved that the observed production executable reports the expected source-tree identity. It explicitly did not claim bit-for-bit reproducible binaries across builders.

v1.8 closes a narrower, testable part of that gap: two independent GitHub-hosted runners build the exact same candidate from the same repository commit and digest-pinned Docker build definition, extract the gateway executable, and compare SHA-256 identities.

## Constitutional invariant

`A_out <= A_in`

Build reproducibility is provenance evidence only. Binary equality cannot authorize requests, create HumanJudgment, mutate policy, promote production, or substitute for a release decision.

## Gates

### G1 — Historical integrity
- `v1.7.0` must remain fixed to `9847b293f3b37a574568ba4e450797b312a44984`.
- Historical v1.7 production evidence remains unchanged.

### G2 — Exact candidate identity
- Both rebuilds must checkout the same full candidate SHA.
- Moving branch identity is not accepted as build identity.

### G3 — Independent rebuild isolation
- Rebuild A and rebuild B execute as separate GitHub jobs on separate hosted runners.
- Both use the repository Dockerfile whose Rust base is pinned by digest.
- Neither build receives production secrets or Railway credentials.

### G4 — Executable identity reconciliation
- Each job extracts `/usr/local/bin/nexus` from its independently built image.
- Each computes SHA-256 over the executable.
- The reconciliation job fails closed unless the two 64-hex digests are exactly equal.

### G5 — Source/runtime continuity
- The canonical source-tree digest function remains present.
- v1.7 runtime provenance and the current Railway durable `/data` boundary remain historical evidence layers separate from v1.8 rebuild evidence.

### G6 — Claim discipline
- PASS permits only: same candidate + stated pinned build definition + two independent GitHub-hosted runners produced byte-identical gateway executables in this run.
- PASS does not establish reproducibility across arbitrary operating systems, CPU architectures, Rust versions, future runner images, providers, or build systems.
- PASS does not prove source correctness, provider correctness, universal security, universal availability, or epistemic correctness.

### G7 — Operational economy
- No production mutation is required.
- No Railway service, volume, deployment, or paid upgrade is required.
- No secret value is recorded in evidence.

### G8 — v1.8 release gate
- The exact release-intent commit must pass `NEXUS Verification`.
- The independent rebuild workflow for that same exact SHA must PASS.
- The release workflow must independently validate both run identity and rebuild evidence before creating `v1.8.0`.

## Production boundary

v1.8 does not modify production. At stage start, Railway reports `nexus-stage-d` deployment `b0e78cf8-af51-4092-9bf6-99e1ac5cc13b` as `SUCCESS`, with the existing durable volume mounted at `/data`.

## Completion rule

No real independent rebuild equality -> no PASS -> no v1.8 seal.
