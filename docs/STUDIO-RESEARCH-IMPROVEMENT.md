# Bounded research draft improvement

Operator-authenticated POST /studio/api/research/improvement takes the original critique request with candidate, expected reference draft digest and optional strict boolean repair_consent (default false). First rerun critique against the exact reviewed inputs. If already consistent, return the unchanged draft; if inconsistent and no consent, return findings but no repaired draft. With consent, reconstruct the structured draft from the complete canonical reference, including all claims, source links, perspectives and uncertainty items, and recheck against the same input. Reject rather than return a failed repair. At most one repair round is performed because the deterministic reference is the intended fixed point; repeated application is a no-op. Return candidate digests bound to the reference, before/after finding counts and an explicit human-review requirement. This does not persist, overwrite or authorize any action. Initial findings can be truncated; repair uses the complete reference instead.

This is structural repair, not general model-generated prose improvement, semantic validation, evidence authentication, calibrated confidence or independent audit. Both checks use the same rules; zero findings do not prove scientific truth. No provider calls, extra dependencies, background tasks or browser integration. Transport cap 384 KiB; nested research input cap 256 KiB. Existing critique cardinality constraints apply. Exact-head CI required.
