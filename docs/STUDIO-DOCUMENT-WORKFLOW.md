# Integrated document retrieval workflow

POST /studio/api/documents/workflow/review and /run accept 1–3 original TXT/DOCX files and a lexical query. The gateway computes extraction and search review identities; clients no longer need to construct separate extraction/search review requests. Each request inspects each file once and reuses server-owned parsed blocks through the existing search validation. Review returns counts, hashes, privacy findings and limitations, no excerpts. Run requires an unchanged review hash and explicit boolean consent, and returns the same evidence bundle as the standalone evidence API, with descriptors for reconstructing the original evidence request. No base64 echo, provider call, generation, persistence or provider consent. File transfer to Studio itself requires user review before upload in a future UI. Existing file, aggregate, query and response bounds remain. Lexical retrieval is incomplete; source truth, semantic relevance and privacy are not guaranteed. The new endpoints are server-side; the existing chat planner is not yet wired to upload files or execute this workflow. Exact-head CI required.
