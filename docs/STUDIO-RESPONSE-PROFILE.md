# Explicit per-request response profile

The existing authenticated /studio-api/respond and /studio-api/respond-stream completion paths now accept optional response_profile with fixed language (auto/en/fa/es/fr/de/ar), detail (auto/concise/balanced/detailed), format (auto/prose/bullets/steps/table), and tone (auto/neutral/professional/friendly). No free-form strings, extra fields, or inferred preferences are accepted. Omitted or all-auto profiles preserve the exact original system policy. Non-default selections append only fixed server-owned instructions to the frozen base policy. The current explicit user request takes priority over style defaults; evidence standards, material uncertainty, safety and authority remain unchanged. Provider routing, attempt budgets, explicit consent and configuration review remain in place. The same request path serves buffered and streaming adapters. The profile is not persisted, automatically learned, retrieved from memory, or sent as a separate user message. Existing clients remain compatible; UI selection and explicit preview integration are not yet implemented. Consent is a caller assertion covering submitted request fields, not proof of a human preview. Model compliance with style or evidence constraints is not guaranteed; mock transport tests check wire behavior, not live model quality. Exact-head CI required.
