# NEXUS Product Architecture

## Purpose

NEXUS is not an automated decision-maker. It is an infrastructure for making human judgment more explicit, inspectable, and evidence-aware.

## Decision lifecycle

```text
Question
  -> Clarification
  -> Goals / Constraints / Values
  -> Claims / Evidence / Provenance
  -> Alternatives
  -> Consequences / Uncertainty
  -> Challenge / Counterarguments
  -> Human Judgment
  -> Audit Record
```

## Authority model

| Object | Producer | Authority |
|---|---|---|
| User question | Human | Human |
| Value / constraint | Human | Human |
| External evidence | External source | Source-dependent |
| Machine analysis | Machine | None over human judgment |
| Alternative | Human or machine | None by itself |
| Human judgment | Human | Human |
| Execution request | Authorized constitutional path | Policy-defined |

The distinction between **origin** and **authority** is intentional. A machine-generated statement can be useful without becoming authoritative.

## Product boundaries

The first usable product should expose five capabilities:

1. **Ask** — capture a question in natural language.
2. **Structure** — turn the question into a Decision Workspace.
3. **Evidence** — record claims with provenance and uncertainty.
4. **Challenge** — surface counterarguments and missing assumptions without issuing a binding recommendation.
5. **Decide** — let the human explicitly record the final judgment.

## Constitutional rules

1. Machine analysis cannot implicitly populate `HumanJudgment`.
2. The UI must distinguish evidence, interpretation, option, and human decision.
3. No AI component may directly cross the execution boundary.
4. Authorization must remain inside the constitutional core.
5. Verification evidence must be generated by CI; it must not be declared by application code.
6. A failed or absent verification run cannot be represented as a sealed release.

## Roadmap

### v0.2 — Epistemic foundation
- Decision Workspace domain model.
- Claims, provenance, uncertainty, alternatives, and explicit human judgment.
- Deterministic serialization tests.

### v0.3 — HTTP/API boundary
- Read/write workspace API.
- Shape validation and envelope handling only at the gateway.
- Constitutional authorization remains downstream.

### v0.4 — Human web workspace
- Question-first UI.
- Evidence and alternatives panels.
- Explicit human judgment control.
- Provenance/history view.

### v0.5 — Analysis adapter
- Pluggable AI analysis.
- Counterargument and assumption extraction.
- No authority escalation.

### v1.0 — Verified NEXUS
- Real CI verification.
- Artifact 05 sealed.
- Attested verification bundle.
- Publicly inspectable release evidence.
