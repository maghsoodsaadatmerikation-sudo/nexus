# Adaptive Studio review routing

Authenticated /studio/api/workflow/adaptive/review and /progress use explicit task, privacy and quality selections to create bounded review-only workflows for document answers, DOCX privacy, manuscript review, research synthesis, paired statistics and general chat. Reuses the existing DAG and progress validation. Each handoff names an existing review API and boundary, not executable parameters. Device-only requests are blocked from server/provider routing; this endpoint itself is server-side and its output does not certify local execution. External provider steps require provider_allowed preference, compatible configured slots and separate exact-payload consent at the operation itself. Comparative critique needs two configured slots; this does not establish reviewer independence. Unavailable requested routes expose blockers and only reviewable fallback steps. Progress recomputes exact route and configuration IDs and rejects stale or dependency-incomplete acknowledgments. No automatic intent classifier, dispatch, real completion proof, live availability, UI or deployment. Exact-head CI required.
